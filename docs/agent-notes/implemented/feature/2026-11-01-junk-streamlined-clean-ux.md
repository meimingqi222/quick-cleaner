# Agent Note: 智能清理前置零弹窗与后置正向反馈减负重构

Status: implemented

## Problem

用户在实机使用智能清理后反馈两处核心交互负担过重：
1. 每次点击「立即清理」无论是否有应用占用都会弹出长篇红色免责声明、计划规则 ID（`development, engine, package-windows, windows`）与技术操作术语确认框；同时，非浏览器桌面应用（如 Notion、Termius 等 Electron 应用）没有写入 `browsers.toml` 声明表，清理前不会被识别询问。
2. 清理结束后页面顶部展示长达数十行的「上次清理已跳过 52 项（正在使用或无法确认）」逐行账单与每行重复的「退出应用后重试」按钮，且收尾阶段在后台跑 4 秒 Restart Manager 归属探测拖慢响应，部分跳过的活跃缓存尾巴还继续留在主列表保持勾选，给用户造成「清理到处失败」的强烈挫败感。

## Decision

按用户批准的设计方案调整智能清理交互契约：

- **无占用零弹窗，有占用集中询问一次。** 点击「立即清理」后在后台 worker 运行 `core.FindRunningApps`：
  - 若未检测到运行中的占用应用，直接启动清理，不再弹出常规清理确认框。
  - 若检测到 1 个或多个运行中的应用，弹出 `ConfirmCloseApps` 对话框，按应用合并展示名称与涉及缓存体积，支持全选/取消全选，底部提供「取消」「跳过占用直接清理」「关闭并清理 (N)」三按钮（全部取消勾选时主按钮切换为「直接清理」）。GUI 关闭宽限期由 8 秒缩短为 4 秒。
- **清理前百毫秒级多应用首锁抽样。** 新增 `platform.FindLockedCacheOwners`（8 路并发排他首锁抽样，每目录上限 64 文件 / 50ms、总预算 400ms），对命中的首个锁文件通过全局 Restart Manager 会话识别同用户、非系统、非关键且不在 QuickCleaner 自身进程树/启动祖先链中的应用；单应用且无省略锁时零额外会话直接归属，多应用或含被省略的系统/自身锁时按 `%APPDATA%` / `%LOCALAPPDATA%` 应用桶并发精确归属。`core.FindRunningApps` 融合 `browsers.toml` 声明通道与动态锁通道（同名应用合并去重、体积不重复累加）；持有 `Executables` 证据的应用在关闭阶段按完整可执行路径精确匹配，防止误关同名异路径进程。
- **正向成果条替代跳过账单。** 移除清理后的 `identifyCleanupOccupants` 探测与 `SkippedDetails` 逐行重试面板，新增顶部 `JunkCleanBanner` 正向展示释放体积与清理文件数（存在活跃占用跳过时附一句温和灰字说明，支持 `×` 关闭）；仅真实权限或异常失败进入默认折叠的 `FailedDetails`。
- **当次扫描视图自动收敛。** `applyJunkCleanResult` 将完全成功及仅剩活跃锁尾巴（`FailInUse` / `FailUnverified`）的目标从当次扫描视图中收起并取消勾选；存在真实错误的目标保留在列表、刷新 `RemainingLive` 并取消勾选；用户在 `ConfirmCloseApps` 中主动不关闭（或点击「跳过占用直接清理」）的应用缓存目标保留在主列表、自动取消勾选并挂上运行中应用徽章。

## Alternatives considered

- **保留无占用时的通用确认框，只删掉规则 ID 文案。** 同类成熟清理工具对已勾选缓存均为一键开清，多一次无信息量的确认点击仍是纯摩擦；文件树透视与软件残留等不可逆高危视图各自保留原有确认策略即可。
- **清理前对所有缓存目标全量跑 Restart Manager。** 几千个文件耗时超过 10 秒；首锁抽样找锁只需毫秒级内核打开，仅对少量抽中锁文件做一次合并会话查询即可兼顾百毫秒响应与全桌面应用覆盖。
- **清理后继续把剩有 1 个锁文件的缓存目录留在主列表并保持勾选。** 用户再点一次清理仍会撞上同一把活跃锁，形成死循环；当次视图收起并由顶部成果横幅统一提示更符合预期，重新扫描仍会如实反映磁盘现状。

## Consequences

- 普通无占用清理实现一键直达，收尾省去最多 4 秒的归属探测等待。
- Notion、Termius、VS Code 等未写入静态规则表的桌面应用在锁住缓存时也能在清理前一次性集中询问关闭。
- 清理后页面不再出现大面积跳过账单；历史记录（`RecordHistory`）中的 `skipped` 与 `failed` 精确叶子分类计数保持不变，供排障与审计使用。
- 保留独立的 `cache_release.go` 能力与测试边界，但不再从跳过账单逐行暴露重试按钮。
